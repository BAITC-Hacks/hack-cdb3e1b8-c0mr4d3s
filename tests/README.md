# Проверки проекта

Все тесты и QA-инструменты находятся в этой папке и используют текущий пакет `scripts/`. Отдельная рабочая копия main больше не требуется: ветка qa/tests содержит собранное приложение.

```powershell
python -m unittest discover -s tests -t . -v
python tests/run_all_checks.py
```

Запускайте из корня репозитория в установленной проектной .venv. Полный запуск создаёт логи и summary.json в test_results/ и не обращается к Telegram или Gemini. Нужен выключенный `gemini.enabled`; устаревшее `bot.runner_module` нужно удалить из config.json.

| Набор | Число | Содержание |
|---|---:|---|
| Тесты участников main | 38 | Команды, запуск, контракт, оценка, SQLite и миграция с WAL |
| test_qa_check.py | 11 | Проверяющий код выявляет намеренно ошибочные реализации |
| test_agent_resilience.py | 7 | Плохие пилоты, NaN/Inf, сбои, ограниченные ресурсы |
| test_demo_eval.py | 9 | Один запуск Agent.act и исходный скоринг, пилоты, seed, пути и команды |
| test_bot_storage_failures.py | 3 | Ошибки сохранения и восстановление из нового процесса |
| test_submission_entrypoint.py | 1 | Корневой Agent работает вне каталога проекта без бота и SQLite |

Всего 69 тестов. Они запускаются одним discovery без двойного подсчёта. Моки внешних вызовов используются в тестах сбоев; интеграционные проверки действительно запускают Agent и исходный scoring_core.

Полный запуск дополнительно проверяет корневые команды local_eval.py/make_submission.py, 11 seed строгого QA, два CSV-экспорта, совпадение корневого и пакетного экспорта, четыре offline-сценария Gemini и bot --once с сохранением результата.

`qa_check.py` возвращает 2 при успешной проверке своего ограниченного набора, поскольку сам по себе не проверяет Telegram. Полный runner учитывает этот код; 1 означает ошибку. Общий успешный runner возвращает 0. Финальный отчёт отдельно указывает, какие живые проверки не выполнялись.

source_manifest.json фиксирует неизменённые файлы исходного main. После намеренного изменения такого файла нужно обновить сведения о проверяемой версии, а не выдавать старый результат за новый.

Доказательства проверки и ограничения: [FINAL_QA_REPORT.md](FINAL_QA_REPORT.md), [FINAL_RESULTS.json](FINAL_RESULTS.json). Предыдущие реализации QA доступны в истории Git; они не дублируются в текущем дереве проекта.
