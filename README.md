# HackAlem: агент тарифных кампаний и Telegram-бот

Агент изучает историю смен тарифов, проводит пилоты и выбирает кампании с учётом бюджета и охвата. Telegram-бот запускает расчёт, показывает отчёт и сохраняет историю в SQLite.

## Структура

```text
scripts/
  agent.py           # стратегия, интерфейс JsonLLMClient и адаптер Gemini
  bot.py             # Telegram-команды, SQLite и офлайн-запуск
  config.py          # настройки, загрузка config.json и безопасное логирование
  environment.py     # среда пилотов и её локальная мок-модель
  local_eval.py      # общая оценка для бота и CLI, создание submission.csv
  scoring_core.py    # исходные правила скоринга организатора
  __init__.py

data/                # все CSV для экспериментов
  submission.csv     # создаётся командой --submission
  bot/runs.sqlite3   # создаётся ботом, исключён из Git

tests/               # автоматические проверки
  bot_eval.py        # прежняя оценка для сравнения результатов в тестах

start_bot.cmd        # запуск бота, поддерживает аргументы командной строки
config.example.json # шаблон настроек
config.json         # личные настройки и ключ Gemini, исключён из Git
requirements.txt    # закреплённые зависимости
```

Инструкции, `AGENTS.md`, описание ТЗ и PDF остаются в корне. Локальный `.env` с токеном Telegram также хранится в корне. Пути к настройкам и данным считаются от корня проекта и не зависят от текущей папки процесса.

## Установка и команды

Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path config.json)) { Copy-Item config.example.json config.json }
```

```powershell
# Один прогон агента с полным отчётом
.\.venv\Scripts\python.exe -X utf8 -m scripts.local_eval

# Проверка устойчивости по десяти seed
.\.venv\Scripts\python.exe -X utf8 -m scripts.local_eval --runs 10

# Создание data/submission.csv с seed=42
.\.venv\Scripts\python.exe -X utf8 -m scripts.local_eval --submission

# Агент, отчёт бота и SQLite без Telegram
.\start_bot.cmd --once

# Telegram-бот; также можно открыть файл двойным щелчком
.\start_bot.cmd

# Офлайн-тесты
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

`start_bot.cmd` сам переходит в корень проекта. Остальные Python-команды запускаются из корня через `-m scripts.<модуль>`.

## Как работает агент

1. Группирует аудиторию по текущему тарифу и ARPU-сегменту; по умолчанию рассматривает группы от 300 до 5 000 абонентов.
2. По `data/change_tariff.csv` оценивает переходы с исходным ARPU от 100 и минимум 10 наблюдениями. Для каждого сегмента выбирает целевой тариф.
3. При включённом Gemini уточняет порядок гипотез. Ошибка API, отсутствие ключа или некорректный JSON возвращают исторический порядок. Если кандидатов не больше числа пилотов, модель не вызывается.
4. Проводит до 12 SMS-пилотов по 150 абонентов, проверяя остатки лимитов. Объединяет историческую оценку с наблюдением и учитывает шум пилотов.
5. Выбирает до 10 непересекающихся SMS-кампаний с положительной консервативной оценкой. Если таких нет, выбирает доступную бесплатную push-кампанию.

Среда и скоринг нужны при каждом реальном локальном прогоне: среда выполняет пилоты, скоринг считает их вместе с финальными кампаниями. Мок-модель построена на выданной истории и не предсказывает результат на скрытой среде судейства.

```python
from scripts.agent import Agent
from scripts.environment import make_mock_env

env, _ = make_mock_env(seed=42)
campaigns = Agent().act(env)
```

Внешний LLM можно подменить через `Agent(llm_client=my_client)`. Объект должен реализовать `generate_json(prompt, schema)`. Интерфейс и Gemini-адаптер находятся в `agent.py`, настройки и промпт — в `config.py`.

## Настройки

Полный шаблон — [config.example.json](config.example.json). Для личных значений используйте `config.json` в корне. Отсутствующие файл или поля заменяются значениями по умолчанию; некорректная структура вызывает ошибку.

| Секция | Назначение |
|---|---|
| `history` | История переходов, минимальный ARPU, число наблюдений и сегменты. |
| `strategy` | Размеры сегментов и пилотов, число кампаний, поправка на неопределённость. |
| `gemini` | Включение модели, ключ, модель, ограничения запроса и промпт. |
| `logging` | Уровень и формат логов; токены и детали внешних исключений скрываются. |
| `bot` | `backend`: `real` или фиксированный `mock`; `db_path`: путь к SQLite. |

Gemini по умолчанию выключен. Для включения задайте `gemini.enabled=true` и `gemini.api_key`; для воспроизводимой локальной сдачи используйте `false`. Промпт `gemini.ranking_prompt` поддерживает `{max_pilots}`, `{pilot_size}`, `{sms_cost}` и `{candidates_json}`.

Параметр `bot.runner_module` больше не нужен: бот вызывает `scripts.local_eval.run_demo`. Старое значение `bot_eval` принимается для совместимости; другие значения нужно убрать. Код из `tests/` при запуске бота не загружается.

По прежнему соглашению команды только токен Telegram читается из `TELEGRAM_BOT_TOKEN` в окружении или корневом `.env`; ключ Gemini хранится в JSON. Запуск, команды и диагностика Telegram описаны в [BOT_README.md](BOT_README.md).

## Данные, проверка и сдача

Все исходные таблицы находятся в `data/`: профиль аудитории, история переходов, трафик, месячный ARPU и справочники. Состав колонок и требования кейса — в [PARTICIPANT_GUIDE.md](PARTICIPANT_GUIDE.md).

`--submission` сохраняет только финальные кампании. При передаче кода сохраняйте пакет `scripts/` целиком, `requirements.txt` и данные в `data/`. Точка входа агента — `from scripts.agent import Agent`.

Тесты проверяют команды бота, SQLite, конкурирующие запросы, настройки, логирование, обработку ошибок и совпадение результатов с прежним оценщиком в `tests/bot_eval.py`. Telegram и Gemini в тестах не вызываются.
