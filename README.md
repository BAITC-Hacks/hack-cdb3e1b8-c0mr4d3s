# hack-cdb3e1b8-c0mr4d3s
Hackathon team repository for C0mr4d3s

## agent.py

Первая часть решения — агент выбора тарифных маркетинговых кампаний. Он изучает историю смен тарифов, формирует гипотезы, проводит пилоты через предоставленную среду и возвращает список финальных кампаний с учётом бюджета и охвата.

Точка входа: `Agent().act(env) -> list[dict]`. Объект `env` предоставляет профиль аудитории, справочник тарифов, параметры каналов, остатки лимитов и метод `run_pilot()`.

### Что реализовано

1. Аудитория группируется по текущему тарифу и ARPU-сегменту. По умолчанию рассматриваются группы от 300 до 5 000 абонентов. Для каждой группы рассчитываются размер и средний `predicted_arpu`.
2. Из `data/change_tariff.csv` берутся переходы с исходным ARPU от 100. Относительное изменение ARPU ограничивается диапазоном от −1 до 3. Для оценки перехода требуется минимум 10 исторических наблюдений.
3. Предварительная оценка использует среднее изменение ARPU, долю перехода среди смен исходного тарифа и параметры SMS-канала. Для каждого сегмента выбирается один целевой тариф.
4. При включённом Gemini модель `gemini-3.6-flash` определяет приоритет гипотез перед пилотами. Она получает агрегированные сведения о сегментах и возвращает JSON со списком идентификаторов кандидатов. Агент проверяет количество, уникальность и допустимость идентификаторов. Если кандидатов не больше числа запланированных пилотов, обращение к модели не требуется.
5. Проводится до 12 SMS-пилотов по 150 абонентов. Перед каждым вызовом проверяются доступные контакты, бюджет и число пилотов. При стандартной стоимости SMS это до 1 800 контактов и 7 200 у.е.
6. Историческая оценка уточняется результатом пилота: `(50 × prior + n × observed) / (50 + n)`, где `n` — фактический размер пилота. Для отбора применяется поправка на шум: `0.5 × 0.8 / √n`.
7. Кампании с положительной консервативной оценкой сортируются по ожидаемому чистому приросту на контакт. Агент выбирает до 10 SMS-кампаний, которые полностью помещаются в оставшиеся лимиты. При оценке дополнительного эффекта учитывается, что участники пилотов уже контактированы. Финальные сегменты не пересекаются.
8. Если положительных вариантов нет, агент выбирает одну бесплатную push-кампанию по лучшей доступной оценке. При ошибке LLM используется исторический порядок гипотез; ошибка отдельного пилота позволяет перейти к следующей гипотезе.

Возвращаемая кампания имеет следующий формат:

```python
{
    "campaign_name": "sms_tariff_4_MID_tariff_8",
    "filter_current_tariff": "tariff_4",
    "filter_arpu_segment": "MID",
    "target_tariff": "tariff_8",
    "channel": "sms",
}
```

### Технологии и структура

Для локального окружения используется Python 3.14, pandas — для работы с таблицами, Google Gen AI Python SDK — для обращения к Gemini. Конфигурация описана стандартными `dataclasses`, интерфейс LLM — через `typing.Protocol`, логирование — через стандартный модуль `logging`. Точные версии прямых и транзитивных зависимостей закреплены в `requirements.txt`.

| Файл | Назначение |
|---|---|
| `agent.py` | Подготовка гипотез, пилоты, обновление оценок и выбор кампаний. |
| `config.py` | Dataclass-структуры настроек, значения по умолчанию, загрузка и валидация JSON. |
| `config.json` | Локальные параметры, промпт и API-ключ; файл исключён из Git. |
| `llm.py` | Интерфейс `JsonLLMClient` и адаптер `GeminiClient`. |
| `logging_config.py` | Создание общего логгера и настройка без дублирования обработчиков. |

Другой провайдер подключается объектом с методом `generate_json(prompt, schema)`, возвращающим разобранный JSON: `Agent(llm_client=my_client)`. Текущий готовый адаптер — Gemini. Ошибки внешних вызовов обрабатываются агентом с возвратом к историческому ранжированию.

### Установка и запуск

Команды выполняются из корня репозитория в PowerShell. Для нового окружения:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для запуска на локальной среде из пакета кейса:

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "import json; from agent import Agent; from mock_environment import make_mock_env; env, _ = make_mock_env(seed=42); campaigns = Agent().act(env); print(json.dumps(campaigns, ensure_ascii=False, indent=2))"
```

Команда печатает JSON с выбранными кампаниями. `agent.py` содержит класс агента; выполнение самого файла без вызова `act(env)` кампании не запускает. Для интеграции с уже созданной средой достаточно:

```python
from agent import Agent

campaigns = Agent().act(env)
```

### Конфигурация

Настройки агента, настройки бота и ключ Gemini читаются из `config.json`, расположенного рядом с `config.py`. Исключение — токен Telegram: по договорённости команды он читается из `TELEGRAM_BOT_TOKEN` в окружении или локальном `.env`. Ключ Gemini из `.env` не загружается.

Для новой установки скопируйте `config.example.json` в `config.json`, только если личного файла ещё нет. В шаблоне Gemini выключен, а поле ключа пустое. Ниже — конфигурация для работы **с включённым Gemini**; замените пример ключа своим и сохраните имеющиеся настройки бота:

```json
{
  "bot": {
    "backend": "real",
    "runner_module": "bot_eval",
    "db_path": "bot_data/runs.sqlite3"
  },
  "history": {
    "relative_path": "data/change_tariff.csv",
    "min_arpu": 100,
    "min_samples": 10
  },
  "strategy": {
    "min_segment_size": 300,
    "max_segment_size": 5000,
    "max_pilots": 12,
    "pilot_size": 150,
    "max_campaigns": 10,
    "prior_weight": 50,
    "per_customer_std": 0.8,
    "uncertainty_penalty": 0.5
  },
  "gemini": {
    "enabled": true,
    "api_key": "YOUR_GEMINI_API_KEY",
    "model": "gemini-3.6-flash",
    "timeout_ms": 10000,
    "max_attempts": 1,
    "temperature": 0,
    "max_output_tokens": 1024,
    "thinking_budget": 0
  },
  "logging": {
    "level": "INFO",
    "format": "%(levelname)s %(name)s: %(message)s"
  }
}
```

Замените `YOUR_GEMINI_API_KEY` своим ключом; не копируйте эту заглушку поверх уже заполненного ключа. `config.json` и `.env` исключены из Git. Без JSON-файла или отдельных полей используются значения по умолчанию из `config.py`: отсутствие секции `history` или `strategy` не означает, что агент не настроен. По умолчанию Gemini выключен; для работы без внешнего API установите `gemini.enabled` в `false`. Отсутствующий ключ, недоступный API или некорректный ответ модели приводят к историческому ранжированию. Некорректная структура конфигурации вызывает ошибку при загрузке.

`bot.backend=real` запускает агента на локальной мок-среде; это не фиксированные демонстрационные цифры. `bot.runner_module=bot_eval` использует текущий адаптер бота. После получения `demo_eval.py` от участника 2 поменяйте только `runner_module` на `demo_eval`. Все расходы и контакты включают пилоты.

Проверка настроек без вывода ключей и без сетевых запросов:

```powershell
.\.venv\Scripts\python.exe bot.py --check-config
```

Прогон агента со скорингом и записью в SQLite, без Telegram:

```powershell
.\.venv\Scripts\python.exe bot.py --once
```

При `gemini.enabled=true` этот прогон может обращаться к Gemini. Успешный результат не доказывает использование LLM: при ошибке агент использует историческое ранжирование, а при числе кандидатов не больше `strategy.max_pilots` не вызывает модель. Для воспроизводимой локальной сдачи используйте `gemini.enabled=false`. Запуск Telegram и команды описаны в [BOT_README.md](BOT_README.md).

Поле `gemini.ranking_prompt` позволяет переопределить промпт. В шаблоне доступны `{max_pilots}`, `{pilot_size}`, `{sms_cost}` и `{candidates_json}`. Если поле пропущено, применяется встроенный шаблон из `GeminiConfig`.

Конфигурация загружается при создании `Agent`; после изменения JSON создайте новый экземпляр. Также можно передать готовый объект настроек через `Agent(settings=...)`. Пути к конфигурации и истории вычисляются относительно файлов проекта. API-ключ скрыт из строкового представления dataclass и не выводится в лог.
