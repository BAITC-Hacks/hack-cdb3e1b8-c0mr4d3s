## Что важно после упрощения

1. Текущая точка входа — `from scripts.local_eval import run_demo`. Бот импортирует её самостоятельно. Старое `bot.runner_module: demo_eval` больше не поддерживается; переносить его в новый config.json нельзя. Наш старый demo_eval.py остаётся исторической реализацией для предыдущей структуры.
2. Фиксированный seed=42 для демонстрации подходит: каждый /run реально вызывает агента, но одинаковые исходные данные и seed дают воспроизводимый результат. Устойчивость дополнительно проверена на других seed.
3. Полный metrics в run_demo содержит дополнительные показатели. ROI может быть Infinity при нулевых расходах. Бот корректно оставляет четыре согласованные метрики перед сохранением, и этот случай проверен. Для другого JSON-клиента нужна такая же нормализация.
4. `PASS` скоринга означает положительный net_arpu_gain. Это не самостоятельное подтверждение всех правил кейса или готовности к сдаче.

## Незакрытый вопрос сдачи

Исходный PARTICIPANT_GUIDE.md из комплекта организаторов требует agent.py, submission.csv, `python local_eval.py` и `python make_submission.py`. Исходный local_eval.py импортирует `from agent import Agent`.

После реорганизации корневого agent.py и make_submission.py нет. Сейчас работают `from scripts.agent import Agent`, `python -m scripts.local_eval` и экспорт в data/submission.csv. README нового main уже отмечает это расхождение. Изменённое командой описание в PARTICIPANT_GUIDE.md не заменяет требования организаторов.

Перед сдачей нужен комплект с совместимыми точками входа и всеми зависимостями, проверенный на исходном комплекте, либо подтверждение организаторов о приёме новой структуры. Проверенный CSV создан и сохранён; одна его успешная генерация не закрывает вопрос упаковки agent.py. Код других участников ради этого в данном QA-прогоне не менялся.

## Живой Telegram и доступ

Бот @hackalemcomradesbot работает на компьютере участника. После получения кода из GitHub тестировать его функции и SQLite можно на любом настроенном компьютере — доступ к машине автора для этого не нужен. Ник бота позволяет пользоваться командами, но не предоставляет его токен, файлы, терминал или SQLite.

В этой проверке внешняя доставка Telegram заменялась тестовыми объектами. Запущенный у участника процесс, его версия кода и настоящая SQLite не проверялись. Пользователь уже вручную проверял команды в Telegram; это отдельное ручное наблюдение без подтверждения версии после обновления.

Для окончательного живого показа владелец обновляет свой код и запускает единственный polling-процесс, затем проверяются `/run` → `/last` → `/history` и история после перезапуска. Альтернатива для независимого теста — отдельный тестовый бот и его токен, заданный локально через TELEGRAM_BOT_TOKEN. Токен не нужен для наших автоматических тестов и не должен попадать в GitHub или отчёт.

## Git и дальнейшая работа

Рабочий репозиторий пользователя на Desktop не переключался и не перезаписывался. Проверенная копия находится отдельно; это снимок файлов конкретного коммита, а не результат `git pull` в пользовательской ветке.

Тесты для новой структуры публикуются отдельно в `qa/tests`, папка `qa/simplified/`. Старые QA-файлы сохраняются для старой версии. Ветки не сливаются; main не изменяется. Для текущего main используйте новые тесты с `--project`, указывающим на отдельную копию main. Сам факт переключения на qa/tests не обновляет её приложение до main.

Безопасный вариант получить main самостоятельно, из локального репозитория:

```powershell
git status --short
git fetch origin
git worktree add --detach ..\hack-main-qa-review 60879fb53477ca6d30baa0449427ef6613381bf9
```

Последняя команда создаёт соседнюю папку для чтения и проверки выбранного коммита. Текущую qa/tests и незакоммиченные файлы она не смешивает с main. Если такая папка уже есть, команда завершится ошибкой; существующую папку удалять не нужно. `git pull origin main` внутри qa/tests для этой задачи не нужен: он может начать слияние.

Итоговый статус этой проверки: **автотесты PASS; готовность к сдаче PARTIAL**. Остались проверка упаковки для организаторов и живой показ обновлённого бота на машине владельца.
