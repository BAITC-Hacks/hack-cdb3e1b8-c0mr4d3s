# QA для упрощённого репозитория

Проверенная версия main: `60879fb53477ca6d30baa0449427ef6613381bf9`.
Этот набор адаптирует QA из `qa/tests` на `60881c4` к новой структуре main. Код приложения в этой ветке может быть старым: проверяйте отдельную копию main.
Старые команды для корневых agent.py/bot.py/demo_eval.py к этой структуре неприменимы.

## Запуск полного набора

Из корня qa/tests укажите соседнюю копию проверяемого main:

```powershell
python -m venv ..\hack-main-qa-review\.venv
..\hack-main-qa-review\.venv\Scripts\python.exe -m pip install -r ..\hack-main-qa-review\requirements.txt
..\hack-main-qa-review\.venv\Scripts\python.exe -B qa\simplified\run_all_checks.py --project ..\hack-main-qa-review --output qa_results
```

Если `.venv` уже настроена, достаточно последней команды. Для QA используйте отдельную копию без секретов. `gemini.enabled` должен быть `false`; `bot.runner_module` удалён из актуальной конфигурации. Telegram-токен для этих проверок не нужен. Установка зависимостей обращается к сети; сами проверки используют локальную мок-среду и заменяют внешние вызовы.

Скрипт проверяет версии 32 зависимостей, 68 тестов, штатную оценку на seed=42 и 0–9, строгую проверку лимитов на 11 seed, два независимых экспорта CSV и сохранение результата реального агента через бот в SQLite. В каждом запуске создаётся отдельная папка логов. Существующий data/submission.csv восстанавливается после проверки; если его не было, остаётся новый экспорт.

Происхождение исходников проверяется по qa_source_snapshot.json, если он есть. После намеренного редактирования проверяемого кода старый снимок больше не подтверждает его версию: сохраните этот файл с результатами предыдущего прогона и создайте новый проверенный манифест либо запускайте QA без него. Не обновляйте хэши лишь ради зелёного статуса.

## Что входит в 68 тестов

| Набор | Число | Назначение |
|---|---:|---|
| tests/ от участников | 38 | Команды бота, изоляция чатов, последние 5 записей, запуск, ошибки, миграция SQLite с WAL, оценка |
| test_qa_check.py | 11 | Наш проверяющий скрипт действительно замечает намеренно испорченные реализации |
| test_agent_resilience.py | 7 | Плохие пилоты, NaN/Inf, сбой пилота, малые бюджет/охват, размеры пилотов |
| test_demo_eval.py | 9 | Канонический scripts.local_eval.run_demo, один Agent.act, исходный скоринг, пилоты, seed, путь, команды |
| test_bot_storage_failures.py | 3 | Ошибка записи/завершения, восстановление после ошибки, чтение из нового процесса |

Тесты не складывают демонстрационные ответы вместо реального агента: контрактные и интеграционные проверки проходят через Agent и scoring_core. Только специальные тесты сбоев используют контролируемые подмены.

`metrics` у run_demo содержит полный результат скоринга. В нём ROI при нулевых расходах может быть Infinity. Перед SQLite бот сохраняет только четыре согласованные метрики, и тест проверяет строгий JSON на этой границе. Полный ответ run_demo нельзя бездумно передавать строгому JSON-клиенту.

## Отдельные команды

Команды приложения ниже запускаются **из корня отдельной копии main**, не qa/tests.

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -B -m scripts.local_eval --runs 10
.\.venv\Scripts\python.exe -B -m scripts.local_eval --submission
.\.venv\Scripts\python.exe -B -m scripts.bot --once --backend real --db qa_demo.sqlite3
```

`--backend real` означает реальный локальный агент на мок-среде. Это не рассылка клиентам и не обращение к Telegram. `--backend mock` выдаёт фиксированную иллюстрацию и не заменяет проверку агента.

Дополнительно проверены `check_gemini.py --mode offline`, `timeout`, `invalid_json`, `invalid_ids` на seed=42. Повтор из qa/tests: `..\hack-main-qa-review\.venv\Scripts\python.exe qa/simplified/check_gemini.py --project ../hack-main-qa-review --mode timeout --report qa_results/timeout.json`. Эти режимы не вызывают Google. Режим `live` в этом прогоне не использовался.

## Ограничения и сдача

PASS в метриках scoring_core означает положительный чистый результат. PASS автотестов означает успешное прохождение перечисленных проверок. Ни одно из них не доказывает балл скрытой среды, работу Telegram-сервера или готовность упаковки для судей.

Исходный PARTICIPANT_GUIDE.md организаторов требует agent.py, submission.csv и команды local_eval.py / make_submission.py. В main сейчас scripts/agent.py и data/submission.csv; корневых точек входа нет. Перед сдачей нужны совместимые точки входа и проверка на исходном комплекте либо подтверждение организаторов о приёме новой структуры. Изменённое описание в репозитории не меняет исходное требование.

Живой @hackalemcomradesbot работает на компьютере участника. Эти проверки не читают его диск, конфигурацию и базу; локальная история отдельная. Для переноса запуска нужен код, зависимости и локально заданный TELEGRAM_BOT_TOKEN. Один и тот же токен не следует одновременно использовать для двух polling-процессов; для независимого живого QA удобен отдельный тестовый бот.

Автоматические результаты: PASS. Живая доставка Telegram: не проверялась этим прогоном. Готовность к сдаче: PARTIAL.
