# QA агента и демонстрации

Эта папка принадлежит участнику, который тестирует решение. Код участников
`agent.py`, `demo_eval.py`, `bot.py` и выданный скоринг здесь не заменяются.
Проверки выполняются на моках; локальные значения не предсказывают балл судей.

## Запуск

Нужен Python с `pandas` и `numpy`, а также зависимости самой команды.
Скрипту нужен путь к папке, где лежат `agent.py`, `local_eval.py`,
`scoring_core.py`, `mock_environment.py`, `environment.py`,
`make_submission.py`, `customer_profile.csv` и `data/` из пакета участников.
При другой структуре репозитория передайте соответствующую подпапку.

```powershell
python qa/qa_check.py --project . --runs 10 --report qa_report.json
```

Пока агент не готов, можно проверить шаблон в отдельной копии пакета:

```powershell
python qa/qa_check.py --project "C:\path\participant-kit" --agent-module agent_template --runs 10 --report qa_report.json
```

Выполняются seed 42 и seed 0..9. Каждый прогон и каждый экспорт запускаются
в отдельном процессе; таймаут по умолчанию 600 секунд на процесс, включая загрузку.
Скоринг вызывается через исходный `local_eval.evaluate_agent`.
Падения агента, пустой ответ, некорректные кампании, отсутствие пилотов,
повторение финального сегмента и обрезка по общему бюджету/охвату попадают в отчёт.
Обрезка одной кампании до 5000 контактов — предупреждение, как допускает скоринг.
Повторение сегмента и зависимость от обрезки общих лимитов — требования плана
команды, а не автоматическая дисквалификация по правилам организаторов.

Дважды вызывается исходный `make_submission.build_submission` с seed 42 в
разных процессах и сравниваются SHA-256 CSV. Файл сдачи не перезаписывается.
Перед реальной сдачей отдельно выполните оригинальные команды:

```powershell
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
```

Если доступны `agent.py` и `demo_eval.py`, проверяется один вызов `run_demo(42)`:
вызов `Agent.act` ровно один раз; финальные кампании и число пилотов относятся
к этому запуску; метрики совпадают с вызванным исходным скорингом; учитываются
пилоты и финальные кампании; результат сериализуется в строгий JSON.
Отсутствующий модуль отмечается `NOT_TESTED`.

Код выхода `1` означает найденные ошибки, `2` — доступные проверки прошли,
но тестирование неполное. Общий статус пока не становится PASS: автоматические
тесты реального Telegram-бота/SQLite ещё требуют его кода. `metrics.status`
из исходного скоринга — отдельная величина: PASS означает положительный
экономический результат, а не успешное выполнение всех QA-проверок.

## Самопроверка тестового инструмента

11 регрессионных тестов внедряют заведомо ошибочные агенты и реализации
`run_demo`: падение, пустой список, неверный тариф, дубли, превышение плана,
двойной запуск, подмена метрики, пропуск пилотов, невалидный JSON.
Положительные сценарии проверяют отсутствие ложной ошибки.

```powershell
$env:QA_PROJECT = 'C:\path\participant-kit'
python -m unittest discover -s qa -p 'test_qa_check.py' -v
```

## Что добавить после появления bot.py

| Проверка | Ожидание |
|---|---|
| `/run` | Вызывает только `run_demo(42)` ровно один раз; показывает net, расходы, пилоты и кампании |
| SQLite после `/run` | Сохранены дата, seed, метрики, кампании, ошибка запуска |
| `/last` | Читает сохранённый результат без повторного вызова агента |
| `/history` | Последние пять записей, от новых к старым, стабильный порядок при одинаковой дате |
| Пустая база | Понятный ответ для `/last` и `/history` |
| Сбой `run_demo` | Ошибка сохранена; бот отвечает и обрабатывает следующий запрос |
| Два `/run` | Нет блокировки event loop и повреждения записей; понятная очередь или отказ при занятости |
| Перезапуск | Запуски доступны после открытия нового соединения SQLite |
| Конфигурация | Токен читается из переменной окружения; импорт модуля не запускает polling |

Первый этап — моки Telegram API и временная SQLite-база, токен не нужен.
Реальная демонстрация потребует токена тестового бота в переменной окружения,
доступа к Telegram и тестового чата. В чат с Codex токен присылать не нужно.

Необходимо отдельно проверить, что решения агента действительно зависят
от ответов пилотов: имеющиеся smoke-проверки подтверждают вызовы и учёт,
но не доказывают качество или адаптивность стратегии.
