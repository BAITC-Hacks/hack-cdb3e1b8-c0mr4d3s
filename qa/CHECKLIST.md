## Telegram и SQLite: сначала моки

| Сценарий | Ожидаемый результат |
|---|---|
| `/run` | Только один вызов `run_demo(42)`; показ чистого результата, расходов, пилотов и кампаний |
| Сохранение | Дата, seed, метрики, кампании, ошибка; успешный результат восстанавливается без потерь |
| `/last` | Последняя запись из SQLite, без нового вызова агента |
| `/history` | Последние пять записей от новых к старым; стабильность при одинаковых датах |
| Пустая база | Понятный ответ; исключения нет |
| Сбой `run_demo` | Ошибка сохранена, пользователь получил ответ, следующий запуск возможен |
| Перезапуск | Новый процесс/соединение видит сохранённые записи |
| Два `/run` | Понятная очередь либо отказ при занятости; нет блокировки обработки команд и повреждения записей |
| Ошибка SQLite | Не сообщается ложное успешное сохранение |
| Несколько чатов | Уточнена и проверена область видимости истории: общая для команды или отдельная для чата |
| Импорт `bot.py` | Не начинает polling самопроизвольно |
| Токен | Из переменной окружения по договору пользователя; отсутствует в коде, логах и БД |

Моки Telegram API и временная SQLite не требуют токена. Для окончательного
показа нужен тестовый бот с токеном, введённым локально, и тестовый чат.
Полный ручной сценарий: `/run` → `/last` → `/history` → перезапуск → `/last`.
