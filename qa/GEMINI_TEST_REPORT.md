## Устойчивость к ответам пилотов

`test_agent_resilience.py` вызывает реальный `Agent.act` на настоящей мок-среде.
Пилоты действительно расходуют бюджет/контакты; изменяются только наблюдаемые
ответы. Служебные данные среды использует тестовый стенд, агент их не получает.
Gemini принудительно отключён и проверяется отсутствие вызова адаптера.

- При всех отрицательных наблюдениях остаётся допустимый план с push-каналом.
- Положительные и отрицательные наблюдения дают разные решения агента.
- После сбоя первого пилота агент продолжает последующие пилоты.
- NaN, +Inf, -Inf не приводят к недопустимому финальному плану.
- При бюджете 600 учитываются расходы пилота; финальные кампании используют push.
- При лимите 2000 контактов остаются ресурсы для финальных кампаний.
- Размеры пилотов 10 и 200 проверены при максимуме 20 пилотов.

В каждом сценарии проверяются корректность кампаний через исходный валидатор,
остатки ресурсов и отсутствие пересечения финальных сегментов. Последнее —
договор и поведение текущего агента, а не новое правило дисквалификации.
Эти проверки не доказывают оптимальность стратегии на неизвестных эффектах.


В двух процессах конфигурация Gemini была включена, но эти экспорты не

не гарантирует детерминированность будущих ответов модели.

Предыдущие два offline-вызова `build_submission` также совпали. Их SHA-256
при нормализации строк в LF:

```text
0894f6af2bfd1c39fd7fcea73da458ba2bb452582bd788987854c8957914c0c1
```

Эти два вида хешей используют разное представление перевода строк и не
предназначены для прямого сравнения. Скоринг во всех оценках — исходный
`scoring_core` через `local_eval`; отдельная формула не создавалась.
Подробные наблюдения без ключей и локальных путей: [TEST_RESULTS.json](TEST_RESULTS.json).

## Незакрытые вопросы

1. Согласовать владельца `demo_eval.py/run_demo`, затем проверить реальную интеграцию.
2. Проверить команды бота, SQLite, ошибки и повторные запросы по [чек-листу](CHECKLIST.md).
3. Зафиксировать режим LLM для сдачи. В ТЗ описан `OPENAI_API_KEY` из окружения;
   текущий необязательный Gemini-адаптер читает `gemini.api_key` из локального
   `config.json`. Без LLM агент работает; это не подтверждает совместимость
   включённого Gemini с окружением судей.
4. Проверить формат сдачи дополнительных `config.py`, `llm.py`,
   `logging_config.py` и данных: один `agent.py` без зависимостей не импортируется.
5. Повторить финальные штатные команды после последнего изменения приложения.

Общий статус QA: **PARTIAL**. Экономический `metrics.status: PASS` относится
к мок-скорингу отдельного запуска, а не ко всей готовности проекта.
