стоит оставить одну реализацию оценки, например сделать в `bot_eval.py`

изменение, в данную публикацию оно не входит.

## Контракт

```python
run_demo(seed: int = 42) -> dict
# {
#   "seed": int,
#   "campaigns": list[dict],  # только финальные кампании
#   "n_pilots": int,
#   "metrics": {
#       "net_arpu_gain": number,
#       "total_cost": number,
#       "total_contacts": int,
#       "status": str,
#   },
#   "error": str,  # присутствует только при исключении Agent.act
# }
```

Последовательность: создать одну мок-среду → один раз вызвать `Agent.act(env)` →
получить фактические пилоты, включая их `explicit_ids` → оценить пилоты и финальные
кампании исходным `scoring_core`. Данные читаются относительно файла модуля.
Telegram и SQLite здесь не импортируются, своей формулы оценки нет.

Seed должен быть неотрицательным Python `int`; `bool`, строки, дроби и `None`
отклоняются до создания среды. При исключении агента уже оплаченные пилоты
сохраняются в оценке, а в `error` попадает только тип исключения. Ошибки загрузки
данных или скоринга передаются вызывающему коду для сохранения как сбоя запуска.

Санитизация финальных кампаний и максимум 10 следуют исходному оценщику.
Пустой ответ агента оценивается как пустой план, но не становится корректным
по требованию кейса 1–10 кампаний: это отдельно обнаруживает строгий QA.
`metrics.status: PASS` означает положительный мок-результат, не готовность всего проекта.

## Безопасная проверка участником без переключения рабочего бота

Из корня своего репозитория с чистым рабочим деревом создайте новую отдельную
копию. Каталог `beeline-eval-check` должен ещё не существовать:

```powershell
git status
git fetch origin
git worktree add --detach ..\beeline-eval-check origin/main
$review = (Resolve-Path ..\beeline-eval-check).Path
if (Test-Path -LiteralPath "$review\demo_eval.py") { throw 'В main уже есть demo_eval.py; сначала сравните версии.' }
if (Test-Path -LiteralPath "$review\qa") { throw 'В main уже есть qa; сначала сравните версии.' }
git -C "$review" restore --source origin/qa/tests --worktree -- demo_eval.py qa
py -3.12 -m venv "$review\.venv"
$python = Join-Path $review '.venv\Scripts\python.exe'
& $python -m pip install -r "$review\requirements.txt"
Push-Location $review
try {
    & $python -B qa\test_demo_eval.py --project .
    & $python -B -m unittest discover -s tests -v
} finally { Pop-Location }
```

Это не сливает ветки и не меняет рабочую базу. Для точного повторения отчёта
в `worktree add` замените `origin/main` на SHA в начале документа. При новом
упрощённом `main` сначала сверяйте совместимость, а не переносите результат
проверки старого коммита на новый автоматически.

В новой тестовой копии без личного `config.json` можно создать минимальный
конфиг ниже. **Не заменяйте им существующий личный конфиг рабочего бота.**

```json
{
  "gemini": {"enabled": false},
  "bot": {"backend": "real", "runner_module": "demo_eval"}
}
```

После этого из тестовой копии:

```powershell
.\.venv\Scripts\python.exe bot.py --once --db bot_data\qa_demo.sqlite3
```

Результат должен сохраниться в отдельной тестовой базе. Этот режим не подключается
к Telegram. Включённый Gemini может сделать API-запрос, поэтому для offline
проверки используется `gemini.enabled: false`.

## Переключение рабочего бота владельцем

1. Убедиться, что рабочая версия соответствует проверенной, и сохранить свои
   незакоммиченные изменения. Получить `demo_eval.py` и тест в эту копию
   согласованным переносом файлов; не заменять весь репозиторий QA-веткой.
2. В существующем `config.json` установить только `bot.runner_module: "demo_eval"`.
   Режим `bot.backend` должен быть `"real"`. Сохранить ключи, параметры агента
   и путь рабочей SQLite. Токен Telegram остаётся в окружении/исключённом `.env`.
3. Остановить прежний процесс и запустить один экземпляр бота обычным способом.
4. Выполнить `/run`, запомнить ID, метрики и кампании; вызвать `/last` и `/history`.
   Чтение истории не должно добавлять новый запуск.
5. Перезапустить бот и убедиться, что `/last` восстанавливает тот же ID и результат.
   При намеренно выбранной новой базе старая история в ней не появится.
6. Зафиксировать SHA приложения и выбранный runner в отчёте команды.

В текущем боте аргументы `/run` отклоняются, seed всегда 42 — это соответствует
плану демонстрации. Разные seed проверяются через eval и локальные тесты.
Одинаковый seed воспроизводит выборки среды, но не гарантирует одинаковый ответ Gemini.
